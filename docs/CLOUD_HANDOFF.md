**The five open blockers of the audit are repaired**, each with a test that fails without the fix (`tests/cloud-audit.test.mjs`):
- `rs-seat-claim` (S1): the first owner token shown binds the room, whoever sits in the seat, so a stray tab with no token cannot leave a room without an owner for good. This reverses the old rule "a token cannot take a seat that someone else already holds in a room not bound to it" (`tests/remaining-engine.test.mjs`, "Relay owner", changed on purpose); the real client always sends a token.
- `rs-keytable-lockout` (K1): `pruneKeys` forgets a pid gone longer than `GHOST_MS` that sent a snapshot too, after those that only greeted; the table no longer fills for good.
- `relay-1` (I1, I2): a full room drops the connection silent longest (at least `IDLE_MS`, 5 minutes; never the instructor's seat) and a full relay forgets the quietest room, instead of turning the newcomer away. A script that keeps its sockets in use is **not** stopped by this: that needs a limit per address, which is the operator's (a campus NAT, a proxy).
- `relay-2` (N1, N2): the client treats close code 1008 as final (`refused`), does not retry, and tells the player what to do (ask for a new room). The trust-on-first-use race itself (a classmate binds a Founder ID in a new room first) is **not** closed; it is inherent to the scheme and the author's call.
- `deal-room-and-games-read-xp-oracle` (X1 to X5): a Read whose lot stays on the shelf with its truth hidden is paid on its confidence, not on how close it came, and tells the quests nothing; its accuracy is kept on the lot and told once when the truth stops being a secret (bought, lost at auction, gone from the shelf), so catching a counterfeit is still earned. An Academy lesson's sandbox is exempt (Read the Room waits for the truth). `docs/BALANCE.md` has the rule.

### 1. The Academy coach card: done, by rule (`d00f6b6`, `af6db6f`)

## Publishing while the gate is red (added 2026-10-30)

The Pages workflow runs the whole suite and deploys only if it passes, and since v2 was merged it has not: the live site (`last-modified` 27 October) is still the old build. A push to `main` always runs the tests first. To publish a build the tests have passed on your own machine while a runner-only failure is being fixed: **Actions > Deploy to GitHub Pages > Run workflow**, tick **skip_tests**, run. The test job is skipped and the deploy runs once; the next push is gated again. `tests/finish-site.test.mjs` pins that the switch is off by default and that a push never skips the tests.
